WHY THIS FILE WAS REVISED
─────────────────────────
The first version of this change also switched the app to a Responsive
layout. In Studio it looked fine. In Preview (F5) and the player, the yellow
header and background stretched across the whole window while the form
(Work Date to Comments) shrank to a small block at the top center.

Cause: the original app uses Scale to fit ON and Lock aspect ratio ON. The
player zooms the whole canvas to the window, so the 700-pixel form looks
large. Responsive turns Scale to fit off, so the player draws everything at
real pixel size. Studio hides this because it zooms the canvas to fit the
editing pane.

Decision: drop the responsive part. Keep the new names, the new save
message, and the Open Sans font. Every layout value goes back to the
original.


HOW TO READ THIS FILE
─────────────────────
- Changes are grouped by control. Finish every property of one control,
  then move on to the next one.
- BEFORE is the value in the original app (Log_v1).
- AFTER is the final value to paste.
- "DEV NOW" appears only where the dev app still has a value from the first
  attempt. Replace that value with AFTER. Where BEFORE and AFTER are the
  same, AFTER puts the original value back.
- Paste formulas without an initial equals sign.
- For a property on a locked data card, select the card in Tree view and
  use Advanced > Unlock to change properties.
- Type layout values in the formula bar. Do not drag controls, or Studio
  rewrites the positions.

TESTING IN DEV
══════════════════════════════════════════════════════════════════════
1. Save in dev. Press F5. Expected: the layout matches the production app
   (or how dev looked before 16 Nov). The yellow header is the same
   width as the form (700), and nothing is stretched across the window.
2. Resize the browser window while in F5. Expected: the whole app zooms
   and keeps its proportions (empty bars may appear at the sides). Fields
   do not move or reflow.
3. Check the text. Heading: "iQuery and Mavericks Log" on one line.
   Labels: "iQueries Completed" and "Mavericks Completed". All labels and
   the Recovery Date picker use Open Sans (the Work Date picker and Reason
   dropdown keep their default font). Hover the iQueries input: the
   tooltip says "iQueries Completed".
4. Enter a total of 8 or more and press Save. Expected: "Entry submitted
   successfully." and one new row in the dev SharePoint list, with the
   counts in PNQsCompleted and WilbursCompleted.
5. Enter a total below 8, pick a reason that is not exempt (not Sick,
   Vacation, Training (Consta), New Employee Training or Project), and
   leave the recovery fields empty. Expected: the message says "iQueries
   and Mavericks" and no row is created. Fill both recovery fields and
   save: the row is created.
6. Press the reload icon (IconCancel1). Expected: the form resets, as
   before.
7. Publish to dev, open the dev player link, and repeat steps 1 and 2.
