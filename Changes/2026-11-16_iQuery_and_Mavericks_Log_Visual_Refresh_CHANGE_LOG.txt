Current implementation and requested result
The app has one screen with a fixed 700 × 650 canvas and App layout set to Fixed.
The heading, field labels, and a save message use several names for the same
counts. The heading, field labels, and recovery date input use Verdana.

Use “iQuery and Mavericks Log” for the heading and app display name, and
“iQueries Completed” and “Mavericks Completed” for the two count labels. Let
the existing background fill the Power Apps viewport. Keep the form centered
and cap its width at 700. Use Open Sans wherever Verdana is currently set.

Impact and dependencies
The iQueries card display name feeds its label and input tooltip. The save
message edit changes only the text shown when recovery details are missing.
Keep the existing SharePoint bindings, including 'Daily PNQ Log',
PNQsCompleted, and WilbursCompleted. The iQueries and Mavericks labels apply
inside this app. The linked SharePoint view and Power BI report use their own
labels.
On wide windows, the heading and icons share one row. At widths below 660,
the title sits under the icons so they stay separate. On short windows, the
screen can scroll down to the end of the form. The app fills the available
Power Apps viewport, which may be bounded by the host if the app is embedded.

Apply in the development app
Follow the blocks in order. Read the steps and explanation, then compare
BEFORE and AFTER before pasting. Paste formulas without an initial equals sign.
For a property on a locked data card, select the card in Tree view and use
Advanced > Unlock to change properties. Keep the card and the existing input.
Use the formula bar for layout changes so Studio does not rewrite the
formulas as fixed coordinates when you drag controls.

TESTING IN DEV

1. Save in the dev environment. Confirm the name in Studio settings, then
   open Studio Preview to test the current edits. The screen heading should
   say iQuery and Mavericks Log. Check both count labels and the iQueries
   input tooltip.
2. In Preview, check a wide viewport around 1440 pixels and a narrow
   viewport around 390 pixels. The background and header should fill the
   viewport, the form should stay centered at 700 pixels or less, and all
   inputs and the save icon should fit. The heading should sit below the
   toolbar on the narrow viewport. To verify resizing in the standalone
   player, publish the tested version to dev and open that dev app.
3. Make the dev window short. Expected: scroll to Comments without losing
   any fields. Check that the heading and label text fit and that the
   recovery date picker matches the other edited fonts.
4. From a fresh launch, enter a total of at least 8 and save. Expected:
   the existing success message appears and one new dev SharePoint row
   contains the counts in their existing columns.
5. From a fresh launch, enter a total below 8 and choose a reason that is
   not exempt. Leave recovery details missing. Expected: the recovery
   message says “iQueries and Mavericks” and no row is created. Supply both
   recovery fields and confirm the entry saves as before.

ROLLBACK

In dev, restore the BEFORE values and formulas for the items you applied.
For the layout, set App layout back to Fixed first. Confirm Landscape,
Lock aspect ratio On, Lock orientation On, and Show mobile device
notifications area Off, as reported before the change. Then restore the
screen and control formulas. Restore the app name and description as
plain text. If a Studio property differed from BEFORE when you started,
restore the value you recorded from Studio.
